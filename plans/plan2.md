# 並列開発フローマップ UI 実装計画

## 目的

このプロジェクトを Git リポジトリの棚卸し画面から、複数 agent による並列開発の
現在地、分岐、進行、停止理由、合流見込みをひと目で判断できる管制画面へ発展させる。

既存のリポジトリ状態、コミットグラフ、ブランチ一覧、diff、次に実行する Git
コマンドは失わず、調査用の詳細情報として一段深い階層へ配置する。

## 原因

現状は本体 checkout と linked worktree をプロジェクト単位で一覧できるが、表示の
中心が worktree の存在と現在の Git 状態になっている。そのため次の情報が不足する。

- worktree が存在するだけなのか、現在 agent が作業しているのかを区別できない。
- ブランチがどこから分岐し、どのブランチへ合流する予定なのかをプロジェクト全体で
  比較できない。
- 編集、コミット、テスト、レビュー、入力待ちなどの出来事を時間順に把握できない。
- merged 済みの多数のブランチが、現在進行中の作業と同じ画面上で競合する。
- コミットグラフは選択した checkout の履歴調査には使えるが、複数の並列作業の
  現在地と次の判断を同時に示せない。
- Git から取得できない agent の工程を、現在のデータだけで正確に表示できない。

## 設計原則

1. ホーム画面ではリポジトリ数ではなく、ユーザーが次に判断すべき対象を優先する。
2. プロジェクト画面ではブランチの存在ではなく、分岐から現在までの開発の流れを
   主役にする。
3. Git で観測した事実と agent が通知した状態を分離し、推測で補完しない。
4. 進捗率を推測しない。現在の工程、最後の具体的な出来事、経過時間を表示する。
5. hover は概要確認に使い、同じ情報へキーボードフォーカス、クリック、タップでも
   到達できるようにする。
6. 色だけで状態を区別せず、文字、線種、形状を併用する。
7. 既存の読み取り専用方針を維持し、Git を変更する操作は追加しない。

## 用語

| 具体対象 | 役割 | UI 上の名称 |
| --- | --- | --- |
| 分岐元からブランチ HEAD までの開発経路 | 並列作業の流れを示す | 作業レーン |
| 作業レーン上のコミット、編集、テスト、レビュー状態の変化 | 時系列上の具体的な出来事を示す | イベント |
| 作業レーンで最後に観測されたイベント | 作業の現在地を示す | 作業先端 |
| ブランチが分岐した実際の merge-base | 開発の開始位置を示す | 分岐点 |
| タスクまたは PR が明示する統合先ブランチ | 作業の統合方向を示す | 合流先 |
| 複数の作業レーンとイベントを時間軸上に配置した表示 | プロジェクト全体の進行を判断する | 開発フローマップ |

合流先をタスクまたは PR から取得できない場合は `null` とし、UI には「合流先不明」と
表示する。ブランチ名や命名規則から推測しない。

## 情報階層

画面を次の 3 階層にする。

1. 全プロジェクト一覧
2. プロジェクト管制画面
3. 作業レーン、コミット、ブランチの詳細

選択状態は URL に保持し、再読み込み、戻る・進む、URL 共有で同じ対象を復元する。

## 1. 全プロジェクト一覧

### 目的

すべてのプロジェクトを展開するのではなく、現在ユーザーが確認または判断すべき
プロジェクトを見つける。

### 並び順

次の状態を上から優先する。同じ優先度では最終イベントの新しい順にする。

1. ユーザー入力待ち
2. コンフリクトまたはテスト失敗
3. レビュー待ち
4. 統合可能
5. agent が実行中
6. agent 状態不明だが直近に Git イベントがある
7. 完了または merged

### プロジェクトカード

各カードには次を表示する。

- プロジェクト名とリモートリポジトリ
- 実行中、入力待ち、問題あり、レビュー待ち、統合可能の件数
- 最終イベントの内容と経過時間
- 次に確認すべき作業レーン
- 既定ブランチから最もコミット差が大きい作業レーン
- agent 状態を取得できない場合の「agent 状態不明」表示

既存の worktree 数、merged 数、prunable 数は補助情報に移す。「作業中」の数値として
worktree 数を使用しない。

## 2. プロジェクト管制画面

プロジェクトカードまたはプロジェクト見出しを選択すると、専用 URL の管制画面へ
遷移する。画面上部には次を表示する。

- プロジェクト名
- README から取得した説明。取得できない場合は「説明なし」
- 既定ブランチ
- リモートリポジトリ
- 最終イベント時刻
- 実行中、入力待ち、統合可能、問題ありの集計

タブは次の 4 つとする。

### フロー

開発フローマップを主表示とする。

- 横軸は時間、縦方向はブランチの分岐関係を表す。
- 既定ブランチを基準線として固定する。
- 作業レーンは実際の merge-base から分岐させる。
- レーン末端にはブランチ名、agent 状態、最終イベントからの経過時間を表示する。
- `現在`、`24 時間`、`7 日`、`全履歴`で時間範囲を切り替えられる。
- 現在位置を示す線を表示する。
- 時間スライダーで過去の観測状態を再現できる。
- 現在進行中のレーンを上部、merged または完了したレーンを折り畳み領域に配置する。
- イベント発生時だけ対象レーンを短く強調し、常時点滅させない。
- `prefers-reduced-motion` では強調アニメーションを行わない。

### 作業一覧

開発フローマップと同じデータを表形式で表示する。

| 列 | 内容 |
| --- | --- |
| 作業 | ブランチ名またはタスク名 |
| 状態 | agent が通知した現在の工程。未取得時は状態不明 |
| 最終活動 | 最終イベントからの経過時間と正確な日時 |
| 既定ブランチとの差 | ahead、behind、コミット数 |
| 担当 | agent 識別子。未取得時は未関連付け |
| 合流先 | 明示された対象ブランチ。未取得時は合流先不明 |
| 次の工程 | agent または PR が明示した工程。未取得時は表示しない |

マップと作業一覧は選択対象とフィルターを共有する。

### アクティビティ

Git、agent、テスト、レビューのイベントを時間順に表示する。

- イベント時刻
- 発生元
- イベント種別
- 内容
- 対象作業レーン
- 関連コミットまたは PR

コミット、編集、テスト、レビュー、入力待ちで絞り込めるようにする。

### プロジェクト情報

次の静的情報と保守情報を表示する。

- README から取得したプロジェクト説明
- リモート URL
- 既定ブランチ
- main checkout のパス
- worktree 一覧と状態
- ローカル、リモートブランチ数
- 使用言語と主要ディレクトリ
- 関連付け済み agent タスク
- 最終 fetch 時刻
- merged、prunable、locked worktree
- 明示的に登録または検出できたテストコマンド

説明、使用言語、テストコマンドなどを取得できない場合は、別情報からフォールバック
せず、各項目を未取得として扱う。

## 3. イベントポイントとコミット詳細

### ポイントの意味

開発フローマップ上の Git コミットを円形のイベントポイントとして表示する。分岐点、
merge コミット、作業先端は形状を変え、凡例を常時表示する。

### hover とフォーカス

コミットポイントへの hover またはキーボードフォーカスで、ポイント近傍に一時的な
ポップオーバーを表示する。

表示内容は次の通り。

- コミット件名
- 短縮ハッシュ
- author
- 相対時刻と正確な日時
- 追加行、削除行、変更ファイル数
- 主要な変更ファイル 3 件まで
- ブランチ、タグ、HEAD
- upstream に対する push 済みまたは未 push
- merge コミットの場合は親コミット

ポイントの可視サイズとは別に 24px 以上のポインター用ヒット領域を設ける。
キーボードフォーカスには 2px 以上の明瞭なフォーカスリングを表示する。

### クリックとタップ

- クリックすると選択を固定し、右詳細ペインを開く。
- `Escape` で固定を解除する。
- モバイルでは 1 回目のタップで概要を表示し、概要内の「詳細」を押すと詳細画面を
  開く。
- 左右キーで同じ作業レーンの前後のコミットへ移動する。
- 上下キーで隣接する作業レーンへ移動する。

hover のたびに完全な diff を取得しない。ポップオーバー用集計はグラフデータと同時に
返し、完全なコミット詳細と diff は選択後に取得する。

### 右詳細ペイン

選択対象に応じて内容を切り替える。

| 選択対象 | 表示内容 |
| --- | --- |
| 作業レーン | タスク、agent 状態、差分、最終イベント、合流先、次工程 |
| コミット | コミット情報、変更ファイル、numstat、diff |
| 分岐点 | merge-base、分岐元、分岐後のコミット数 |
| 合流点 | PR、レビュー、CI、競合状態 |
| プロジェクト背景 | プロジェクト概要 |

幅 1200px 以上では sticky ペイン、未満ではドロワーとして表示する。開閉時にマップの
選択位置を失わない。

## データモデル

### Git から取得する事実

- checkout と worktree
- ローカル、リモートブランチ
- HEAD、merge-base、親コミット
- commit author、日時、件名、refs
- numstat と変更ファイル
- dirty、ahead、behind、diverged
- stash、merged、prunable、locked
- fetch 時刻

### agent から取得する事実

最低限、次のイベントを受け取る。

```json
{
  "task_id": "task identifier",
  "worktree": "/absolute/path/to/worktree",
  "phase": "testing",
  "summary": "backend focused tests",
  "occurred_at": "2026-09-04T14:31:20+09:00"
}
```

`task_id`、`worktree`、`phase`、`occurred_at` は必須とする。値が欠けたイベントを別の
値で補完しない。`summary` は `null` を許容し、空であることを明示する。

agent の工程は少なくとも次を区別する。

- investigating
- implementing
- testing
- reviewing
- waiting_for_user
- blocked
- completed
- stopped

Git イベントが新しくても agent の工程は推測しない。agent イベントが無い作業レーンは
「agent 状態不明」と表示する。

### イベント履歴

時間スライダーとアクティビティ表示のため、現在値だけでなくイベント履歴を保存する。

- 一意なイベント ID
- 発生時刻
- 観測時刻
- イベント種別
- 発生元
- プロジェクト ID
- worktree パス
- branch
- commit hash
- task ID
- イベント固有 payload

該当しない項目は `null` とし、空文字列や推測値を入れない。

## API 方針

既存 API を壊さず、プロジェクト単位の API を追加する。

- プロジェクト一覧と判断対象の集計
- プロジェクトの作業レーン一覧
- 指定時間範囲のイベント一覧
- フローマップ描画用の分岐関係
- コミットポイント用の軽量な集計
- 選択コミットの完全な詳細
- agent イベントの受信

グラフの初期表示では表示範囲内のレーンとポイントだけを返す。時間範囲の変更時に
追加データを取得し、既存の 200 コミット上限を無条件に全履歴へ拡張しない。

## 実装段階

### Phase 1: Git 事実だけの開発フローマップ

- ホーム画面をプロジェクト優先の一覧へ変更する。
- プロジェクト管制画面と URL を追加する。
- merge-base、HEAD、コミット日時から作業レーンを描画する。
- コミットポイントの hover、フォーカス、選択、詳細表示を実装する。
- merged、prunable を既定で折り畳む。
- 「作業中」を worktree 数として表示しない。
- agent 固有項目は状態不明として表示する。

### Phase 2: agent と worktree の関連付け

- agent イベントの受信と履歴保存を追加する。
- agent の工程、最終メッセージ、入力待ち、停止を表示する。
- 作業レーンとタスクを worktree の絶対パスで関連付ける。
- 時間スライダーで過去の観測状態を再現する。

### Phase 3: PR、レビュー、CI の合流情報

- PR が明示する base branch を合流先として表示する。
- レビュー待ち、CI 実行中、成功、失敗をイベント化する。
- 統合可能なレーンを判断対象としてホームに表示する。
- GitHub 等との接続が無い場合は PR、レビュー、CI を未取得として扱う。

## 受け入れ条件

### 全体理解

- ユーザーがプロジェクト画面を開いて 5 秒以内に、現在動いている作業レーン数を
  特定できる。
- 各作業レーンについて、分岐元、作業先端、最終イベント、経過時間を確認できる。
- agent 情報がある場合は工程を、無い場合は「agent 状態不明」を確認できる。
- 入力待ち、問題あり、レビュー待ち、統合可能が通常の作業より先に見つかる。
- merged 済み作業が現在進行中の作業を押し流さない。

### コミット操作

- マウスでポイントに hover するとコミット概要が表示され、離れると閉じる。
- キーボードフォーカスでも同じ概要が表示される。
- ポップオーバーは対象ポイントとフォーカスを覆わず、画面端では配置を反転する。
- クリックで詳細を固定し、URL、右ペイン、マップ上の選択が同期する。
- モバイルのタップ操作だけで概要と詳細へ到達できる。
- hover だけで完全な diff API を呼ばない。

### プロジェクト詳細

- フロー、作業一覧、アクティビティ、プロジェクト情報を切り替えられる。
- タブ切り替え、選択対象、時間範囲を URL から復元できる。
- README 説明や agent 状態など未取得の値を推測表示しない。
- 既存の状態、コミットグラフ、ブランチ一覧、diff、次の Git コマンドへ到達できる。

### アクセシビリティとレスポンシブ

- すべての操作をポインターなしで実行できる。
- フォーカス順が画面上の作業レーンと一致する。
- 色だけで状態、ブランチ、イベント種別を区別しない。
- 375px、768px、1024px、1440px で横方向のページスクロールを発生させない。
- 44px 以上のタッチ操作領域を持つ。グラフポイントは可視サイズと別に十分な
  ヒット領域を設ける。
- OS のライト、ダーク、reduced motion 設定に追従する。

### 性能

- 初期表示で全コミットの diff を取得しない。
- 表示範囲外のプロジェクト、レーン、イベントを遅延取得または仮想化する。
- SSE 更新で画面全体や全レーンを再描画しない。
- 更新時にスクロール、ズーム、選択中のポイントを維持する。

### 検証

- backend の実 Git fixture で分岐、merge、複数 worktree、detached、履歴上限外を
  検証する。
- frontend の計算ロジックを単体テストする。
- production build を通す。
- Compose に反映し、実ブラウザで hover、フォーカス、クリック、タップ、URL 復元、
  時間範囲変更を確認する。
- 375px、1024px、1440px の実画面でプロジェクト一覧からコミット詳細まで操作する。

## 非対象

- Git の commit、push、pull、merge、branch 削除を UI から実行すること
- Git の事実だけから agent の状態や進捗率を推測すること
- タスクまたは PR が明示していない合流先をブランチ名から推測すること
- Phase 1 で agent、PR、CI 連携まで同時に実装すること
- 既存のコミット詳細、ブランチ一覧、次の Git コマンド機能を削除すること
