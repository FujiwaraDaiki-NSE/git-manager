# ブランチを軸にした関係の表示

## 達成する状態

Git が観測できる現在の全参照について、ローカル・リモート・detached HEAD を区別し、任意の相手との同一・包含・分岐・共通祖先なし・判定不能を確認できる。過去の分岐・取り込みは PR と reflog の明示的な証拠から表示し、現在の包含だけで過去のマージ操作や作成元を断定しない。

Git はブランチ名をコミットに保存しない。削除・期限切れの reflog、削除済み参照、浅い履歴、失敗した取得は情報の欠落として説明する。復元できない過去を架空の線で補わない。既定ブランチとの共通祖先から作成元を一つに推定する既存処理は、全参照対の現在関係の表示へ置き換える。

## 実装

- `branch_ref_relations`: 各行の全ローカル参照とリモート参照を列挙。一括取得した Git DAG から全組合せの到達関係、固有コミット数、全 merge-base を計算する。
- `branch_relation_events`: reflog の名前を指定したブランチ作成・Fast-forward・通常マージを収集。操作時刻とコミット時刻、ローカル・リモートの参照を分離。曖昧な source は未解決として残す。
- `branch_rows.connections`: PR 証拠を保持し、現在関係と reflog 証拠を統合する。
- UI: グラフの先端にローカル・リモートを明記。期間外の合流は根拠点を表示し、表示行外の関係数を明示。グラフの行数・期間とは独立した参照選択式の全関係一覧と操作記録を用意する。
- 詳細パネルとグラフの意味を合わせ、取り込み済みのローカルと未取り込みのリモートを混同させない。

## 完了条件と証拠

1. 現在の全参照数 n に対し n(n-1)/2 件の比較結果がある。欠落・浅い履歴を無関係と扱わない。
2. FF、通常マージ、複数のマージ元、PR squash/rebase の取り込み、削除された参照、同名 refs、reset、元ブランチの後続コミットをテストする。
3. 名前が分からない作成元、消えた reflog、欠損オブジェクトを未取得・未解決として表示する。
4. `design_db` 実データで UCUM→UI改善の FF 記録、ローカル包含、リモート未包含が API と実画面の双方で分かる。
5. 初期表示・件数制限・期間選択・詳細・狭い画面・キーボード操作で、関係の確認に行き止まりがない。
6. backend tests、frontend tests/build、レビュー（P1を修正）、Compose ビルドとコンテナ反映、反映後の実画面確認が完了する。
7. 開発者向け HTML summary、コミット、開始時ブランチ main を宛先とした PR を作成する。既存の未追跡 backend/uv.lock を保持する。
