# issue #12 ブランチ関係サマリー 実装計画

## 原因

`/api/repo/graph` はコミット行と現在の HEAD レーンだけを返しており、
`origin/HEAD` が示す既定ブランチや、ローカルブランチ HEAD の集合を
フロントエンドが識別できない。そのため既存グラフからブランチ間の分岐点を
求めて要約表示するための入力が不足している。

## 受け入れ条件

- API は `origin/HEAD` から求めた `default_branch`、表示中の既定ブランチの
  `default_lane`、全ローカルブランチの `branch_heads` を返す。
- `origin/HEAD` が無い場合は名前を推測せず `null` を返す。
- グラフタブでは、表示範囲内に HEAD があるローカルブランチが 2 本以上なら、
  既定ブランチのベースライン、各ブランチ HEAD、既定ブランチとの共通祖先から
  HEAD までの経路をサマリー表示する。
- 1 ブランチ、空リポジトリ、共通祖先や HEAD が取得上限外の場合にも崩れず、
  誤った経路を補完しない。
- 色だけに依存せず、ブランチ名と関係のテキスト一覧をアクセシブルな代替情報にする。
- 既存コミットグラフ、コミット選択、ブランチ一覧、`--all` 切替、`GRAPH_LIMIT=200`
  の挙動を変えない。

## 変更

1. `backend/app/graph.py` に既定ブランチとローカル HEAD の取得・レスポンス追加を行う。
2. `frontend/app/types.ts` の API 型を拡張する。
3. 表示中の DAG から共通祖先と強調経路を計算する小さな SVG コンポーネントを追加する。
4. グラフタブの既存コミットグラフ上にサマリーを配置し、既存トークンに沿ってスタイルする。
5. backend の実 Git fixture と frontend の型チェック・production build で確認する。
6. Compose に反映し、実ブラウザ操作で複数ブランチ・単一ブランチ相当・既存操作を確認する。

## 非対象

- Git への書き込み操作
- API の表示件数上限変更
- リモートブランチのサマリー表示
- グラフライブラリの追加
