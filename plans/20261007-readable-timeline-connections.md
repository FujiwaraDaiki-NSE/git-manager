# 20261007 タイムライン接続線の可読化

## 背景
`frontend/app/branch-timeline.tsx` のブランチタイムライン（横軸=時間、行=ブランチ）で、
ブランチ間の関係線（分岐・マージ）が大量に描かれて見にくい。
さらに `timeline-layout.mjs` の `routeTimelineConnections` が縦チャネルのx座標をトラック全幅から選ぶため、
混雑時に始点より左（過去）へ戻る経路が生じ、時間の向きを誤解させる。

## 要件
1. **時間単調な経路**: 関係線は x が単調非減少（左→右のみ）。直交迂回をやめ、始点→終点を結ぶ S 字三次ベジェ
   `M x1 y1 C mx y1, mx y2, x2 y2`（mx は x1,x2 の中点）で描く。x1 > x2 の場合（時刻の逆転データ）は
   線を描かず端点マーカーのみとし、理由をラベル（title）に含める。逆走する線は一切描かない。
   色：分岐(branch)は元ブランチ側、マージ(merge)は取り込まれる側（source）の行色を使う。
2. **既定表示を絞る**: 既定で描くのは各行の「分岐元（その行が target の branch 関係）」と
   「マージ先（その行が source の merge 関係）」のうち、証拠が操作記録(`pull_request` 等 merge_base 以外)のもの、
   および merge_base 推定でもその行の唯一の分岐元であるもの（1行あたり最大 分岐元1本＋マージ先1本）。
   それ以外（同期マージ、推定の追加関係など）は、行ホバー/行フォーカス/接続選択時のみ描く。
   ホバー（またはキーボードフォーカス）した行に関わる線を強調し、他を薄くする。既存の「1本ずつ確認」選択は残す。
   UIに「すべての線を表示」トグルを置き、オンなら全関係を描く。
3. **遠距離はスタブ表示**: 行インデックス差が 4 以上の関係は、既定では線全体を描かず、
   両端に短いスタブ（約24px）と相手ブランチ名のチップ（例「↗ main へマージ」「↙ main から分岐」）を表示する。
   チップ（button）をクリックすると、その関係を選択状態にし線全体を描く。強調中・選択中・「すべて表示」時は線全体を描く。
4. **親子順の行並び**: 行の並び替えに「親子順」（既定）と「更新順」を切り替え可能にする。
   親子順：デフォルトブランチを先頭に、各ブランチを分岐元（branch 関係の source 行。複数なら操作記録優先→
   最も新しい分岐）の子として深さ優先で並べ、兄弟は更新が新しい順。親不明は末尾に更新順。循環は無視して安全に処理。
   表示行数制限（limit）は従来どおり更新が新しい行を選んだ後、その表示集合を親子順に並べる。

## レビュー後の補足（実画面確認で追加）
- 行に固有色がないため、線の色は種類別（分岐=青、マージ=緑）とし凡例を合わせる。
- チップは行上端の細い帯に置き、同じ行・同じ側で複数あれば「↙ N件のマージ元」等の集約チップ1つにまとめる。
  集約チップのクリックで行の関係を固定表示（再クリック・Esc・「固定を解除」で解除）。件数は状態で変化させない。

## 非要件
- バックエンドAPIの変更はしない。
- 全関係一覧（branch-relations.tsx）は変更しない。

## 実装方針
- 純粋関数を `timeline-layout.mjs` に追加/置換（経路生成、既定表示の選別、スタブ判定、親子順並び）し、
  `frontend/tests/branch-timeline.test.mjs` 等で単体テスト（単調性：経路上のxが減らないこと、逆転時は線なし等）。
- `branch-timeline.tsx` / CSS を更新。
- 確認: `cd frontend && npm ci && npm test && npm run build`、コンテナ反映後ブラウザで実画面確認。
