再起動直後のfetch殺到を解消、ブランチ横断の移動・差分・判断待ちの見通しを強化 — 2026-11-21

最優先課題「再起動直後のfetch殺到」は、原因を2つ特定して直し、同条件の実測で解消を確認しました。1つはイベントループ上で全worktree行ぶんのスナップショット鮮度チェック（refs走査）が直列に走り、/api/health すら最大12秒応答しなかったこと。もう1つは、fetchが何も取ってこなくても成功のたびにプロジェクトの全worktreeを再計算していたことです。

開始時30点 + 検証済み加点62点 = 92点（100点未達）。加点基準による評価であり、客観的な品質保証ではありません。
