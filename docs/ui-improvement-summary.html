gitdash · UI改善ループ · 2026年9月29日

状態を読み取りやすく、
操作を途切れさせない画面へ

複数プロジェクトの一覧から、ブランチ・worktree・コミットの詳細までを改善。実データを使ったGUI E2Eで問題を再現し、修正とコンテナ反映を繰り返した。

変更内容

領域内容と理由
プロジェクト一覧見出し、カード、状態バッジ、選択中フィルターを整理。未取得の情報を折りたたみ、検索・並べ替え・表示密度を保ったまま詳細と一覧を往復できる。
操作Ctrl/Cmd+Kでプロジェクト切り替え、/で一覧検索、ライト・ダーク・自動テーマ、パスやコマンドのコピーを追加。
作業一覧変更あり・競合・未push・未pull・worktreeの絞り込みと、名前・要対応・最新コミット順を追加。狭い画面では表をカード表示にする。
履歴とグラフブランチへの移動、取得範囲外の先端の明示、大きな差分の省略案内。多数の関連ブランチは開いて確認でき、閉じている間は個別名の描画を省く。実データの画面要素数は51,080から12,936へ減少。
説明文HTMLで装飾されたREADMEから説明文を抽出。見出し、画像バッジ、スクリプト・スタイル・コード例を説明として表示しない。
状態の正確性未取得を0や正常状態として扱わない。作業パスがないブランチのGit操作を無効化し理由を表示。別プロジェクトの同名ブランチへのagentイベント混入を修正。
継続性と復帰再走査中も検索と表示内容を保持。古い応答を破棄し、通信エラーを明示。プロジェクトとコミット詳細の再試行、入れ子の詳細画面のEscape・フォーカス復帰を調整。開いたまま画面幅を変更しても、最前面の詳細だけを閉じる。

実測した性能改善

94プロジェクトの一覧API1.267秒 → 約0.375秒

Git状態の読み出しを最大4並列に制限。3回の測定は0.373 / 0.378 / 0.374秒。

一覧取得中のhealth応答1.167秒 → 0.002秒

ブロッキング処理をAPIのイベントループから分離。

54ブランチ・1,078コミットの祖先探索15.8秒 → 約3ms

共有祖先の重複探索を除去。全54ブランチで変更前と返す経路が一致。ページ全体の読み込み時間を示す数値ではない。

frontend Docker送信コンテキスト474MB → 372KB

node_modulesとビルド生成物を除外。lockfileに従ってnpm ciを実行。

単一の稼働環境・実データでの測定値。ハードウェアやリポジトリ規模によって所要時間は変わる。

確認結果

  • frontend: 52テスト成功。共有祖先の多い履歴、20,000コミットの深い履歴、絞り込み、ソート、URL状態、イベントの関連付けを含む。
  • backend: 69テスト成功。一覧処理中にもhealth APIが応答する回帰テストを追加。
  • Next.jsの本番ビルド、Dockerビルドと起動を確認。standaloneの成果物が存在することをDockerビルド内で検証。
  • GUI: 実データ94プロジェクト、検索・お気に入り・フィルター・表示密度・戻る操作・再走査・クイック切り替え・グラフ移動・履歴検索を確認。
  • GUI: 320px/390pxとデスクトップ、ライト/ダーク、キーボード操作、コピー、入れ子の詳細画面を確認。モバイル詳細の画面端の切れを修正し、閉じるボタンをスクロール時にも保持。
  • GUI: 通信遮断時のプロジェクト・コミット詳細エラーと再試行、再走査の未確認表示を検証。更新通信だけが失敗した場合も前回の一覧・検索を保持し、古い取得内容であることを明示。ブラウザだけのテスト用レスポンスで入力待ち・競合・未取得・パスなしを確認し、介入を解除。

レビューは依頼どおり実施していない。テストは上記の操作範囲を検証するもので、すべての環境・入力で不具合が存在しないことを保証するものではない。
