検証

backend 466件、frontend 479件、tsc 成功。GUIは Claude の組み込みブラウザで、実データ（thinkplatform / langchain / design_db / git-manager）と一時fixture（12レーンのoctopusマージ、同一HEADの9ブランチ、ステージ済み・未ステージ混在のstash、git am 停止、2つのremoteの main、pushRemote 設定、重なりworktree、テスト用agent報告。確認後に削除）で確認。Codexレビュー10件中6件を採用（--no-textconv、PR取得の全体期限、PR対応先の明示、完全SHA同士のみ比較、件数の対象範囲の明示、デコード不能パスの除外）。

実機で見つけて直した不具合: push設定元の追加で保存済み観測と戻り値の形が食い違い /api/project が500になった（キャッシュ対象の関数名を変更）。

残課題

  • 保存済み観測が変わった直後の最初の1回は解析で2〜4秒かかる（大規模プロジェクト）。
  • ローカル先端とPRのCI対象が「異なる」場合、git am とも rebase とも判定できない rebase-apply の表示は、単体テストのみでGUI未確認。
  • 不採用にしたレビュー指摘: 削除行の選択ステージが同名ディレクトリ配下を巻き込む稀なケース（dry-runで確認可能）、worktree個別のpush設定、SSE再接続中の新着件数、-S の深いページのメモリ。
  • デスクトップ通知本文（判断依頼の質問）のOS上の表示は未確認のまま。
