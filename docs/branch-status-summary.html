ブランチ単位の作業状況報告

MCPの入力を worktree、status、summary の3項目に集約します。エージェントがタスクIDや時刻を生成する必要をなくし、GUIはリポジトリとブランチごとに最新の報告を表示します。

MCPの契約

公開ツールは report_agent_status の1つ。説明文は次のとおりです。

ブランチの作業状況が変わったときに報告する。worktreeには作業中のGitルートの絶対パス、statusには現在の状態、summaryには短い説明（不要ならnull）を指定する。
引数役割
worktree対象を確実に特定するためのGitルートの絶対パス。未知のパスやdetached HEADは拒否します。
status調査中・実装中・テスト中・レビュー中・入力待ち・問題あり・レビュー待ち・マージ可能・完了・中断のいずれかを明示します。
summary短い状況説明。説明が不要ならnullを明示します。
{
  "worktree": "/home/solution2024/git-manager",
  "status": "review_required",
  "summary": "修正とテスト完了。レビュー待ち。"
}

成功応答はテキスト ok のみ。返り値に状態全体や履歴は含めません。イベントIDと時刻はサーバーが生成し、再呼び出しは別の履歴になります。MCPは自動で有効化しません。

hooksとGUIの責任

ブランチの状態は明示的な作業状況報告から表示します。hooksは開始・中断・終了の履歴を残します。たとえば「レビュー待ち」の報告後にSessionEndが届いても、ブランチの状態は「レビュー待ち」を維持します。

同じブランチに異なるセッションやworktreeから報告しても、状態と件数は1ブランチとして扱います。別リポジトリの同名ブランチは分離します。同じ作業ディレクトリでブランチを切り替えても、以前のブランチの報告を移し替えません。hooksだけが届いている場合、作業状況は推測しません。

確認結果

  • バックエンド84テスト、フロントエンド55テストが成功。
  • Next.jsのproduction buildとDocker Composeの検証環境ビルドが成功。
  • 実際のMCP通信で3必須引数・okのみの返り値を確認。
  • 実hooksスクリプトのSessionEnd送信後もブランチのレビュー待ちが維持され、終了は履歴に残ることをAPIとGUIで確認。
  • GUIのライブ更新、ブランチ1件への集約、再読み込み後の状態維持を確認。最終レビューの修正必須事項は解消済み。

互換性と確認範囲

hooks／RESTの既存入力契約と保存済み履歴を維持します。従来のMCPの引数形式は新しい3項目へ置き換わります。GUIの一覧・集計・作業一覧・アクティビティ・過去時点の表示で、ブランチ単位の状態と履歴を分けて扱います。

既存のフロントエンドは別のUI改善worktreeから稼働しているため、今回の変更は独立したCompose環境で確認します。検証用GUIはlocalhost:4413、MCPはlocalhost:8763。通常のlocalhost:4412を上書きしません。
