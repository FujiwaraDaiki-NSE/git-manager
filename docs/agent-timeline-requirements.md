# 全プロジェクトの作業タイムライン要件

- 目的: どのプロジェクト・ブランチで何が進み、何についてユーザーの判断が必要かを詳細画面から離れずに把握する。
- 全ページの共通レイアウトへ常設。狭い画面でも一覧を隠さない。
- 現在の状態: backendのproject agent_tasksにある最新の明示的報告を使用。過去の確認待ちを未解決として扱わない。
- 履歴: 保存された全プロジェクトのagentイベントを新しい順に表示。project、branch、状態またはhook種別、説明、時刻、詳細への導線を持つ。
- lifecycleと判断状態を区別。経過時間やGit状態から作業完了・確認待ちを推測しない。
- 初回と再接続で保存履歴を取得し、SSE更新との重複・順序逆転を防ぐ。未取得・切断・空を区別する。
- MCPは自動実行機構ではない。ユーザー共通指示とツール説明で送信するタイミングを定義する。
- 既存のGit表示・イベント保存仕様・hooksを維持する。
- 検証: frontendテストとビルド、backendテスト、実MCPの保存確認、GUIで一覧・詳細・狭幅・状態更新を確認する。
