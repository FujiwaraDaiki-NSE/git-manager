最優先課題「再起動直後のfetch殺到」を実測で切り分けました。自動fetchのネットワーク処理がリポジトリのロックを握ったままだったこと、背景の状態更新が画面用のスレッドプールを占有していたことを解消し、fetch一巡は約28%短くなりました。ただし起動直後約26秒の全件状態更新中は、他の画面操作が4〜9秒に劣化するため、課題は未解消です。あわせて、PRが大量のリポジトリで60秒ごとに15秒待たされていた問題を解消しました。
