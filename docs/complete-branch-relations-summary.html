ブランチ間の現在の関係と、分岐・取り込みの記録

対象は gitdash のブランチフロー。ローカルの Fast-forward が表示されない問題を起点に、ローカルとリモートを区別し、各参照とすべての相手の関係を調べられるようにした。

判断の根拠

表示する事実根拠混同しない事柄
同じ先端・相手を含む・相手に含まれる・分岐中・共通履歴なし観測した先端 SHA から到達できる Git の親子関係包含だけでは過去に merge コマンドを実行したとは断定しない。
ブランチ作成、Fast-forward、通常マージreflog の操作名、指定された参照名、操作日時、当時のコミットコミットの作成日時と取り込み操作の日時は異なる。SHA 指定の操作からブランチ名を推測しない。
PR による取り込みGitHub が返したマージ済み PR の source/base、SHA、merged_atsquash/rebase により元 SHA が祖先に存在しなくても、PR の記録は保持する。
判定不能・未解決失敗した読み取り、欠損した履歴・参照、曖昧な名前情報不足を「関係なし」にしない。reflog の取得成功を過去すべての復元成功としない。

構成

  • branch_ref_relations.py は行内の全ローカル・リモート・detached HEAD を独立に比較する。全参照対を返し、グラフの200コミット上限には依存しない。
  • branch_relation_events.py は明示的な操作記録を収集する。現在の包含状態と履歴上の操作を分離し、現在のブランチ行に結び付けられない記録も残す。
  • branch_rows.connections はPR、操作記録、現在の全参照比較を一つの応答にまとめる。既定ブランチとの共通祖先だけから作成元を決める線は、全参照の共通祖先表示に置き換えた。
  • フローの先端はローカル・リモートを明示する。期間外の取り込みには根拠点を残し、表示行から隠れた関係数と全関係一覧への導線を表示する。
  • 関係一覧はグラフの行数や表示期間に依存しない。選んだ参照と全相手の比較、記録された操作、未解決の記録を調べられる。

浅い履歴

リポジトリ全体が shallow でも、比較する両参照が同じ欠落境界を共有していれば、欠落した祖先は双方に共通する。比較対象ごとに確定できる差分と、履歴不足で確定できない結果を区別する。

稼働環境への反映

開始時ブランチは main。実装は codex/complete-branch-relations の worktree で行い、共通hooksと環境設定を読む /home/solution2024/.local/bin/gitdash-compose を使用する。Compose のビルド元のみ worktree に指定した一時 override を使い、既存ポート・永続データ・認証の設定を引き継ぐ。

PR を取り込む前に通常の main から再ビルドすると main のコードに戻る。再現用の build override は /tmp/gitdash-complete-branch-relations.compose.yml。
